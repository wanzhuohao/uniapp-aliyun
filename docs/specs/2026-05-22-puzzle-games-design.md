## 游戏 1：24 点

### 规则

- 系统出 4 个 1-13 的数字（扑克牌点数）
- 玩家用 +、-、×、÷ 和括号把 4 个数算出 24
- 每个数字必须用且只用一次
- 中间结果允许是分数（如 `8 ÷ (3 - 8 ÷ 3) = 24`）

### 难度分级

按"解的数量"分级，预生成时计算：

| 难度 | 解的数量 | 例子 |
|------|---------|------|
| 简单 | ≥ 5 解 | `3 6 8 4` |
| 中等 | 2-4 解 | `3 3 7 7` |
| 困难 | 1 解 | `3 3 8 8`（唯一解 `8/(3-8/3)`） |

「困难」档允许出现一些经典刁钻题（如 1378、3478 等）。

### 玩法交互

- 答题区显示 4 张数字卡 + 运算符按钮（+ - × ÷ ( ) =）+ 输入框
- 两种输入方式（选其一实现，**建议方式 B**）：
  - **方式 A**：纯输入框，玩家手写算式（如 `(8-2)*(3+1)`），点提交校验
  - **方式 B**：点击数字卡和运算符自动拼接到表达式条，类似公式编辑器
- 校验逻辑：
  1. 解析表达式，确保 4 个数字恰好各用一次
  2. 用分数运算求值（用 `{num, den}` 而非 float，避免 `1/3 * 3 = 0.9999...`）
  3. 结果等于 24/1 → 通过
- 通过 → 显示「正确！」+ 用时 + 一键下一题
- 卡住 → 提示按钮（展示一个解，但本题不计分）

### 分数与记录

- 简单 +10 / 中等 +20 / 困难 +30
- 用提示后本题清零，但不影响总分累加
- 计时仅作显示，不计入分数
- 存：本周连胜（连续通关数）、累计通关数、最高单局连胜

### 题目生成算法（`utils/games/twentyFour.js`）

```js
// 1. 穷举所有 (1..13)^4 组合（去重排列后约 715 组）
// 2. 对每组用 DFS 穷举所有「2数运算」合并方式 + 所有运算符顺序
//    - 5 种二叉树结构 × 4! 排列 × 4^3 运算符 ≈ 7680 种表达式（含等价化简）
// 3. 用分数类去重计算结果，统计 = 24 的不同表达式数量
// 4. 按解数量分桶到 easy / medium / hard
// 5. 预生成 JSON 落到 static/data/games/twenty-four.json
//    格式: { easy: [[3,6,8,4], ...], medium: [...], hard: [...] }
```

题库大小预估 < 50KB，启动时同 idiom 一样用 `dynamic import` 懒加载。

### 表达式校验

不实现自己的 parser，借助 `Function` 构造器 + 预处理：

```js
function evalExpr(s, nums) {
  // 1. 提取所有数字 token，校验与 nums 多重集相等
  // 2. 校验仅含合法字符 [0-9+\-*/().× ÷ ]
  // 3. 替换 × → * / ÷ → / 后用 BigFraction 求值（fraction.js 或自己写 20 行）
  // 4. 等于 24 返回 true
}
```

不依赖外部库，自己写 100 行内的分数运算 + 表达式 tokenizer 即可（参考社区已有实现）。

## 游戏 2：数字华容道

### 规则

- N×N 棋盘（N=3 或 4），放 1 到 N²-1 数字 + 1 个空格
- 点击与空格相邻的数字格，会与空格交换
- 目标：把数字按 1→N²-1 顺序排列，空格在右下角

### 难度分级

| 难度 | 棋盘 | 名字 |
|------|------|------|
| 简单 | 3×3 | 八数码 |
| 中等 | 4×4 | 经典 15 |
| 困难 | 5×5 | 24 数码 |

默认进入显示三个 tab，玩家自选。3 档全部启用。

### 玩法交互

- 进入页面 → 选择难度 → 棋盘出现，自动开始计时
- 点击数字格滑动到空位（支持点击 + 触摸，**不实现拖拽**，移动设备触摸即可）
- 顶部显示：当前步数 / 计时 / 最少步数（提示）
- 底部按钮：重开 / 一键打乱 / 返回

### 可解性校验（关键）

不能纯 shuffle，必须保证有解：
- **奇数边长 N（3, 5）**：所有非空格数字的逆序数为偶数 → 可解
- **偶数边长 N（4）**：(逆序数) + (空格距底行的行数) 同奇偶（这里同奇要求可解）
  - 实测用：从已排好的目标状态出发，做 100~200 次随机合法移动来打乱（保证一定可解，且打乱程度可控）

**实现选方案 2（随机走步打乱）**，简单可靠。

### 数据结构

```js
state = {
  size: 4,                // N
  board: [1,2,3,...,15,0], // 0 表示空格，长度 N²
  emptyIndex: 15,
  steps: 0,
  startedAt: <timestamp>,
  finished: false
}

function canMove(idx) { /* idx 与 emptyIndex 行/列相邻 */ }
function move(idx)    { /* swap board[idx], board[emptyIndex] */ }
function isSolved()   { /* board[i] === i+1 for i<N²-1, board[N²-1]===0 */ }
```

### 分数与记录

- 不计分，只记录最佳成绩
- 每个难度分别保存「最少步数」和「最短用时」（两个独立 PB）
- 完成时同时展示当局结果 + 历史 PB（破纪录提示）

存储 key：`sliding_puzzle_pb`，结构：
```js
{ 3: { steps: 42, time: 65 }, 4: { steps: 80, time: 180 }, 5: { ... } }
```

## 游戏 3：迷你数独

### 规则

- N×N 棋盘（N=4 或 6 或 9），分若干宫格
- 每行、每列、每宫格内 1-N 各出现一次
- 部分格预填，玩家填空白

### 难度分级（双维度）

棋盘大小 + 挖洞数量：

| 档位 | 棋盘 | 宫格 | 挖洞数（空白） | 适合 |
|------|------|------|--------------|------|
| 入门 | 4×4 | 2×2 | 6-8 | 启蒙 |
| 简单 | 6×6 | 2×3 | 12-16 | 初阶 |
| 中等 | 6×6 | 2×3 | 20-24 | 进阶 |
| 困难 | 9×9 | 3×3 | 35-45 | 标准 |

### 玩法交互

- 进入选难度 → 棋盘渲染，预填数字灰底不可改，空白格可点
- 点击空白格 → 弹出 1-N 数字按钮 + 清除按钮
- 实时校验：填入后若违反行/列/宫规则，该格红色高亮
- 全部填满且无冲突 → 通关动画 + 用时
- 顶部：计时 / 难度 / 错误数
- 底部：重开 / 提示（填一个正确数字，扣 10 分）/ 返回

可选 V1 不实现「铅笔模式」（小字记候选数），后续优化。

### 题目生成（`utils/games/sudoku.js`）

```js
// 1. 生成完整解：DFS 回溯，行/列/宫约束
//    - 4×4: <1ms
//    - 6×6: <10ms
//    - 9×9: <100ms（用随机起始 + 剪枝）
// 2. 随机挖洞：按难度 holesCount 个，每次挖一个洞后用 solver 验证唯一解
//    - 如果挖完后多解，回滚此洞，换下一个位置
//    - 困难档可以放宽到「优先尝试 N 次挖洞」，达不到目标数也接受
// 3. 返回 { puzzle: 二维数组, solution: 二维数组 }
```

### 数据结构

```js
state = {
  size: 9,
  boxRows: 3, boxCols: 3,  // 宫格大小
  puzzle: number[][],       // 0 表示空白
  solution: number[][],     // 正确答案（提示用）
  current: number[][],      // 玩家当前填的状态
  fixed: boolean[][],       // 哪些是预填不能改
  errors: number,
  startedAt: <timestamp>,
  finished: false
}
```

### 分数与记录

- 入门 +10 / 简单 +30 / 中等 +60 / 困难 +120
- 用一次提示 -10
- 每个难度记录最短用时 PB
- 累计通关数

存储 key：`sudoku_stats` 和 `sudoku_pb`

## 通用约定

### 主题色 & UI

- 复用 `PageHeader :theme="game"` 紫色主题（`#7C4DFF`）
- 卡片样式与成语接龙一致：白底紫阴影，圆角 28rpx
- 字体：标题用楷体（`font-family: 'STKaiti', 'KaiTi', '楷体'`）
- 数字格子用等宽字体（避免数字宽度跳动）

### 通用组件抽象

观察到三个游戏都有「计时器 + 步数 + 重开按钮」，**V1 不抽组件**，每个页面自己写（避免过早抽象，参考成语接龙也是一页全栈写）。若 V2 三个页面 UI 出现明显重复再统一抽 `<GameBoard>`。

### 存储策略

不做迁移，schema 变更直接清缓存（CLAUDE.md 项目约定）。

每个游戏独立 key：
- `twenty_four_stats` / `twenty_four_pb`
- `sliding_puzzle_pb`
- `sudoku_stats` / `sudoku_pb`

### 题库 / 静态数据

- 24 点：预生成 `static/data/games/twenty-four.json`，运行时 `dynamic import` 懒加载
- 数字华容道：无静态数据，运行时打乱生成
- 数独：题目运行时生成（4×6 难度都很快，9×9 < 100ms 也可接受）

### 测试

按 CLAUDE.md，HBuilderX 项目无 CLI 自检，每个游戏完成后在浏览器手动验证：
- 题目能正常生成且可解
- 答对/答错的反馈正确
- 计时、计步、PB 记录持久化
- 路由跳转 & 返回正常
- 重开后状态干净

## 风险与开放点

1. **数独题目生成时间**：9×9 唯一解校验可能慢，准备好"生成中"loading；如果实测 > 500ms 改预生成。
2. **24 点分数运算精度**：必须用分数类，不能用 float。
3. **华容道 5×5 难度**：3 档全做，但 5×5 默认折叠或加「挑战」标签，避免小孩误选。
